# 每天 / 每周要做什么（一张卡）

> 这个仓不是一堆工具，是一个 **2 步/天 + 1 张表/周** 的循环。把它贴在手边。

## 每天（约 1 分钟，不含拍片）

**第 1 步 · 前一天就把题定好**（这是唯一没有降级品的环节）

```bash
python tools/new_run.py --title "<今天的题>" --cohort <同题材分组> \
    --who "谁遇到" --wrong-now "现在怎么错" --can-do-after "看完能立刻做什么" \
    --minutes 20 --metric interaction --baseline 0.05 \
    --weak "同类内容最弱的一环" --counter "一条反直觉结论" \
    --date <明天> [--bvid <如果已发布>]
```

- **不过准入卡就不会创建**。硬塞进去的记录会污染整周的中位数。
- 库存低于 7 天时 `python tools/topic_gate.py backlog topics.jsonl --days 7` 会喊停 —— 那天第一件事是补库，不是拍片。

**第 2 步 · 发布后取数**

```bash
python tools/fetch_stats.py <BVID> --run-dir runs/<那一天>
```

它写进去的是 `snapshot_at`（真实取数时刻）。**`at_hours` 只是近似**，因为公开接口只给累计值。

## 每周（约 10 秒）

```bash
python tools/daily_check.py runs --week <一>..<日> \
    --metric interaction \
    --assert "daily>=7" --assert "gaps:3" --assert "stat:n>=5" \
    --assert "gate:who" --assert "meta:title_unique7"
```

一眼看到：哪一天准入没齐、哪一天没记录、互动率有没有连续掉。

退出码：`0` 全过 / `1` 硬断言失败（会指到具体日期）/ `2` 输入不合法。**没有「看起来还行」这种码。**

## 当它判「退步」时，按这个顺序看

1. **连续 3 天低于基线阈值？** → 先看是不是同一题材（cohort 变了不算退步）
2. **准入都齐了吗？** → 有几天是 1/3、2/3，那几天本来就在硬凑
3. **`gaps:3` 过了吗？** → 如果这几天的记录是补写的，数据本身可能不准
4. **都正常但仍退步** → 这才是内容问题，去看那几天的选题卡写了什么

## 它一定会说的两句话（别当成 bug）

- **「不可判定」**：样本不够。它的意思是「现在还看不出」，不是「没问题」。
- **「本窗口可判定的最小退步 X%」**：这个窗口的分辨率。X 很大时，说明这份报告只能看「崩」，看不出「退」。

## 什么时候该放弃这套流程

按 `DECISION-D2-positioning.md`：

- 连续 3 天忘记记录（`gaps:3` 会红）→ 记录太重，改用更轻的方式
- 判定与你自己的判断 80% 以上冲突 → 量化对象错了
- 取数成本 > 10 分钟/条 → 数据链路不成立
