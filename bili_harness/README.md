# bili_harness

带**预算**、**错误分类**、**可录可放**的 B站接口访问层。

## 为什么需要它

直接 `urllib` 打 B站接口，会遇到三种完全不同的失败，而正确反应也完全不同：

| code | 含义 | 正确反应 |
|---|---|---|
| `-799` | 请求过于频繁 | 退避后重试可能恢复 |
| `-352` | 风控校验失败 | **立刻停手**，重试只会更糟 |
| `-101` / `-403` | 未登录 / 权限不足 | 需要人处理 |

把这三类混在一起写的代码，注定会在某天把自己的账号打进风控里。

## 三种模式

| 模式 | 用途 | 联网 |
|---|---|---|
| `live` | 真实取数 | 是，带预算 |
| `record` | 取数 + 落盘 | 是，带预算 |
| `replay` | 测试与演示 | **否**（store 里没有就报错） |

```bash
python -m bili_harness record fixtures    # 录一次
python -m bili_harness replay fixtures    # 之后永远离线
python -m bili_harness video BV1GJ411x7h7 # 单条
```

## 硬约束

- **预算**：默认 30 次/分钟，超了直接抛错，不会悄悄重试
- **回放不联网**：测试里把 transport 换成「一被调用就抛异常」也能过
- **篡改检测**：store 是 JSONL + sha256 链，改一个字节重放就会报错

## WBI 签名

空间/搜索类接口需要签名（`w_rid`）。`sign.py` 实现了公开的混淆表：
`img_key + sub_key` 重排取前 32 位作 mixin_key，`md5(sorted_query + mixin_key)`。

签名能算对，但**不代表接口会放行** —— 空间枚举接口即使签名正确仍返回 `-352`（实测）。
这不是我们的 bug，也不该靠重试解决。
